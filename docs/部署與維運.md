# 部署與維運

## 環境需求

- Node.js：僅本機預覽需要。
- Git：提交與推送網站原始碼。
- Google Apps Script 與 Google 試算表存取權：更新後端程式與檢查報名資料。
- GitHub Pages：目前從 `main` 分支根目錄發布。

## 本機預覽

在專案根目錄以 PowerShell 執行：

```powershell
node preview-server.js
```

瀏覽 <http://127.0.0.1:8000>。結束預覽時回到伺服器終端機按 `Ctrl+C`。伺服器只綁定 loopback 位址，供本機測試，不是正式網站伺服器。

前端語法檢查：

```powershell
node --check app.js
```

專案目前沒有 package manifest 或自動化測試 runner。Apps Script 程式位於 `apps-script/Code.gs`；部署前應在 Apps Script 編輯器確認程式碼已儲存，並檢查執行記錄與部署版本。

## 網站發布（GitHub Pages）

1. 修改前端或文件後，檢查差異並確認沒有提交 `SPEC/` 或其他不應公開的資料。
2. 在本機執行前端語法檢查及[驗收測試](./規格與測試.md)中適用項目。
3. 將變更提交並推送至 GitHub 儲存庫 `lynnlung/2026-tokyo-trip` 的 `main` 分支。
4. 在 GitHub Pages 設定確認來源仍為 `main` 分支根目錄，等待部署狀態完成。
5. 開啟正式網址 <https://lynnlung.github.io/2026-tokyo-trip/>，確認首頁、海報、表單與瀏覽器 Console。
6. 若變更涉及報名流程，必須完成一次合成資料端到端測試，並核對試算表。

GitHub Pages 只負責靜態檔案；它不會部署 `apps-script/Code.gs`。

## Apps Script 更新與部署

Apps Script 專案「2026公司旅遊」與來源檔 `apps-script/Code.gs` 分開管理；目前沒有自動同步或自動部署流程。

1. 在 Apps Script 編輯器更新程式碼並儲存。
2. 以部署管理介面建立新版本或更新既有網頁應用程式部署；確認執行身分為部署者，存取權符合目前公開報名需求。
3. 若更新既有部署並沿用相同 `/exec` 網址，通常不需改前端設定；若產生新的部署 URL，需同步更新 `app.js` 的 `APPS_SCRIPT_URL`，再發布網站。
4. 透過正式網站提交一筆合成資料，核對成功/失敗回覆與試算表資料；特別確認手機前導零。
5. 若部署設定或權限變更，確認 Apps Script 授權與公開網站呼叫均可正常運作。

Apps Script 專案使用部署者的 Google 權限讀寫試算表。不要將擁有者憑證、授權 token 或其他秘密放入前端或儲存庫。

## 資料與故障排除

### 報名畫面顯示失敗

1. 先檢查試算表是否已新增該筆資料；`no-cors` POST 的結果可能已寫入，即使前端後續回呼逾時。
2. 檢查 Apps Script 部署 URL、部署版本、執行記錄及執行授權。
3. 檢查瀏覽器 Network/Console 中 POST 與 JSONP 查詢是否可達；不要複製或分享含個資的請求內容。
4. 確認 Apps Script 的 Script Cache 結果查詢在 300 秒有效期間內完成。
5. 檢查無誤後再讓使用者重送，避免逾時重試造成重複報名。

### 資料未出現在預期試算表

- 確認檔名為「2026公司旅遊」、工作表為「報名資料」，並檢查是否有重名試算表。
- `getOrCreateSpreadsheet_` 會依名稱尋找第一個 Google 試算表；若雲端硬碟中有同名檔案，須人工確認程式使用的正確試算表。
- 確認第一列標題與程式中的 `HEADERS` 順序一致，並檢查 Apps Script 執行記錄。

### 手機前導零遺失

- 檢查電話欄儲存格格式為純文字。
- 確認程式仍以 `setNumberFormat("@")` 設定格式，並以文字值寫入電話。
- 修正後用以 `0` 開頭的合成號碼重新測試；不要以轉成數字的方式處理電話。

## 維護原則

- 修改表單欄位時，同步更新 `index.html`、`app.js`、`apps-script/Code.gs` 的驗證與資料映射、標題列，以及本文件中的規格與測試清單。
- 修改 Apps Script 後，先確認其網頁應用程式部署已更新；僅推送 GitHub 不會更新後端。
- 試算表存有個人聯絡資料。僅授權必要維護人員存取；測試資料使用合成值並依資料管理政策清理。
- 公開端點目前沒有登入驗證、速率限制或垃圾報名防護。若需加上存取控管、反濫用或資料保留政策，須先設計與驗證公開報名流程，不可只在前端加入限制。
- 若要回復前端版本，使用 Git 建立新的回復提交並重新部署 Pages；不要直接刪除或覆寫雲端試算表資料。
